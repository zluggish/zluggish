# Medium tests

Run from `server` with Node 24: `pnpm test:medium`. `pnpm test` runs colocated unit tests (`test:unit`, `src/**/*.test.ts`) and this suite, including in CI. Test files belong beside their implementation or in `tests/medium`; `tests` itself contains only directories for medium tests, shared support and fixtures. The CLI follows the same layout, with migration workflows in `cli/tests/medium`.

Inspired by [Immich's medium tests](https://github.com/immich-app/immich/tree/main/server/test/medium), the medium suite exercises the Hono app, real migrated SQLite databases, file persistence, sessions and shared world state. Runtime fixtures use temporary storage and synthetic riders; teardown closes databases and removes files. Endpoint contract tests run in process. Transport tests also bind local sockets to verify HTTPS, TCP, UDP and DNS. External provider workflows use mocks; no production accounts or data are required. The endpoint contract fixture fails unexpected calls to global `fetch`, including requests whose errors the application catches.

`inventory.json` is a checked-in contract inventory transcribed from `../plans/zluggish-endpoint-compatibility-audit-2026-11-13.md`: 218 legacy method/path pairs, 33 additional pairs, and two newer Zwift connection routes. The suite needs no sibling checkout or plan file at runtime. Each entry specifies its concrete request, anonymous and signed-rider status, content type, and applicable JSON/text/redirect contract. Placeholders select fixture riders. Removed endpoints and deliberately unsupported legacy responses remain explicit. Do not regenerate expectations from application responses to make failures pass; review them against the audit and intended contract.

The inventory test checks every method/path separately, and invalid bearer credentials cannot fall through to a public handler. A registration guard fails when the application adds a route absent from the inventory. The guard matches concrete inventory requests against the registered path patterns, including parameter constraints and shared action handlers.

The baseline cases use empty synthetic storage, missing resource IDs or invalid input. They establish routing, access, response and validation contracts; a passing baseline alone does not establish successful mutation behavior. Stateful suites add upload/list/download/delete and overwrite workflows, profile replacement, imported achievements and route backfill, portal thresholds, activity feeds/media capabilities, goal progress and fitness, meetup notifications and race results, browser CSRF/selection, relay login, social messages, playback and CDN workout bytes. Protobuf responses are decoded with the protocol schemas; persistence and queued messages are asserted where relevant.

The compatibility suites in this directory also cover the audit findings and provider/import workflows. These tests do not certify live Zwift/Companion compatibility or real provider behavior; the audit's differential and real-client acceptance sequence remains applicable.

When adding an endpoint, add an inventory entry with a reviewed contract and a stateful scenario when it changes data. Keep audit behavior changes explicit and check ownership using the second rider. Use fixed clocks for period boundaries and explicit provider mocks for external calls.

## Compatibility regression coverage

The F01–F14 findings have stateful regression coverage in the medium suite:

| Findings           | Test file                                        | Regression boundary                                                                                                                                                                |
| ------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F01–F04            | [storage.test.ts](storage.test.ts)               | Negotiated uploads and stable overwrite timestamps across different seconds; malformed input, JPEG bytes, profile replacement, saved-game badges and portal thresholds             |
| F05, F06, F09, F10 | [events-records.test.ts](events-records.test.ts) | Imported route backfill, public entitlement routing, meetup messages/notification edits and race summary timing                                                                    |
| F07                | [workouts.test.ts](workouts.test.ts)             | Browser home and saved-token Android login trigger provider refresh; coalescing, deadline cancellation, failed-download cache retention, TrainingPeaks and climb schedule delivery |
| F08, F11           | [activities.test.ts](activities.test.ts)         | Mirrored goal progress and startup activity retention without deleting historical feed/detail data                                                                                 |

| F13                | [profiles.test.ts](profiles.test.ts)             | Companion JSON types, DOB/birthday age, equipment/attributes, avatar and response negotiation, explicit false and large integer bounds                                             |
| F14                | [workouts.test.ts](workouts.test.ts)             | Omitted, uppercase/lowercase cycling, running and unsupported sport across all four workout endpoints                                                                              |

`mediumBrowser` signs in through the real picker and follows cookie rotation to obtain the current CSRF token. Provider mocks replace only `fetch`; route handlers, session checks, protobuf codecs, SQLite and filesystem writes remain real. Failed refresh/download cases assert the previous files and metadata remain intact, rather than checking only the HTTP status. Socket tests require permission to bind loopback addresses in a restricted sandbox.
